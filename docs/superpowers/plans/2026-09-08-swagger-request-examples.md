# Swagger Request Examples Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every implemented JSON request-body example in Swagger executable and consistent with the approved API contract, especially fixed `en`/`vi` translation keys.

**Architecture:** Replace the About-only operation filter with one centralized request-example filter keyed by the controller parameter type. Keep runtime validation unchanged; OpenAPI examples document valid payloads while the Application layer remains the enforcement boundary.

**Tech Stack:** .NET 10, ASP.NET Core controllers, Swashbuckle, Microsoft.OpenApi JSON nodes, xUnit integration tests.

**Spec:** `docs/api/API_CONTRACT.md` sections 1–7 and 10; `docs/BUG_LESSONS.md` BUG-2026-008.

## Global Constraints

- Examples cover every currently implemented `application/json` request body.
- Translation objects use only explicit `en` and `vi` keys; no `additionalProp1` placeholder appears.
- Example values satisfy current request structure, enum/string casing, date ordering, URL, publication, child-order, and unique-ID rules.
- Multipart upload schemas remain generated by Swashbuckle and are not represented as JSON bodies.
- No runtime DTO, route, validation, persistence, or database behavior changes.
